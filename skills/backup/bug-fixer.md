# 自动 Bug 检查与修复流程

## 1. 核心原则
**在修复任何代码之前，先读规则，再跑检查，最后精准修改，严禁盲目重写整个文件。**

## 2. 标准工作流程

### 步骤 1：确定问题范围
- 用户可能提供了具体报错信息（终端截图/文字）。
- 如果没有具体信息，则默认检查最近修改的文件或整个项目。

### 步骤 2：分批扫描代码
- **调用 `scan_code_batch` 工具**，从 `offset=0, limit=20` 开始。
- **根据返回结果判断**：
  - 如果返回提示 `🔄 还有剩余文件待检查`，则**自动继续调用下一次**（offset 递增）。
  - 循环直到返回 `🎉 全部扫描完成！`。
- **收集所有批次的问题**，合并成完整的问题列表。

### 步骤 3：分析错误并匹配红线规则
- **调用 `get_rules`** 获取最新的开发红线。
- 将 `run_code_check` 返回的错误与红线规则进行对比：
  - 是否使用了 `<script setup>`？
  - 是否用了 `data()` 选项式写法？
  - 是否存在 `console.log` 未加环境判断？
  - 是否有未定义的变量或导入路径错误？

### 步骤 4：精准修复（最小改动原则）
- **只修改报错涉及的文件和行数**，不要动无关代码。
- **修复策略**：
  - 如果是**格式问题**（缩进、空格）：自动运行 `npx prettier --write [文件路径]` 修复。
  - 如果是**语法/逻辑 Bug**（例如 Vue 响应式丢失、API 调用错误）：重写对应的代码块，并确保符合 `<script setup>` 规范。
  - 如果是**红线违规**（比如用了 `data()`）：将其重构成组合式 API。

### 步骤 5：二次验证（闭环）
- 修改完成后，**再次调用 `run_code_check`** 验证。
- 如果仍有报错，重复步骤 3-4。
- 如果通过，向用户报告修复结果，并列出修改了哪些文件。

## 3. 常见 Bug 场景与解决方案

| 错误类型 | 检查依据 | 修复方法 |
| :--- | :--- | :--- |
| 组件未注册 | 页面报错 `Unknown component` | 检查 `pages.json` 或 `components` 目录下的注册逻辑 |
| Props 缺少默认值 | ESLint 报错 | 补充 `default` 属性 |
| 路径引用错误 | Module not found | 修正 `@/` 别名路径 |
| 响应式丢失 | 数据变了但视图未更新 | 确保使用 `.value` 或 `reactive` 包裹 |
| 生产环境日志泄露 | 发现 `console.log` | 用 `import.meta.env.MODE !== 'production'` 包裹 |
